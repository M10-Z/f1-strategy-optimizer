# 路线图

[English](roadmap.md)

## 产品目标

面对车辆性能差异及会响应的对手，按当前比赛场面规划更好的完赛名次。
单车最短时间是组件基线，不再是最终产品目标。不声称穷尽现实因素或保证最好名次。

## 已实现的研究基础

- 显式轮胎/配置 API，修正后的单车动态规划及独立穷举对照。
- 分组拟合、仅早年训练的留出验证与基线/覆盖报告，JSON/CSV 来源记录。
- 双语终端研究向导、合成演示、情景分析、打包与离线测试。
- FastF1 赛会消息加载、已知删除圈标记检查及清洗排除原因。
- 多车可见状态、一次进站候选、情景加权名次及风险。
- 异质基准速度、胎龄衰退、逐圈交通/有限超车、固定及 undercut/overcut 响应式对手，
  假设 SC/VSC 和湿地损失事件。
- 同时行动隔离、未来事件仅仿真器可见、历史进站时间及假设可用时点检查；
  真实历史回放适配器尚未实现。

## 后续优先级与证据要求

1. **真实数据与验证。** 计时接口目前返回代理 403，先取得可信缓存/规范化数据或允许的
   网络访问。只用此前观测构建决策快照，在留出比赛验证间距/位置、超车、进站损失和
   对手响应窗口。报告覆盖、名次分布校准、风险和失败案例；历史回放不能证明未发生
   策略的因果收益。
2. **可行的自适应规划。** 补充轮胎库存、旧胎胎龄、合法配方约束、多次进站以及带持续
   可见历史的重新规划。以决策前声明的速度/对手不确定性比较策略；区分单车精确最优
   和多车有限候选搜索的结论。
3. **交通与赛道环境。** 用证据改进超车/DRS、套圈、燃油及速度演化、SC 部署/重启、
   湿地配方与天气响应。不能把现有近似参数或示例权重冒充已拟合概率。
4. **车队协作与扰动。** 增加车队标识、共享维修区排队/双车进站、队友目标与配合约束；
   将处罚、故障、退赛、红旗重启作为明确事件/状态转移。具备适当历史暴露量/标签后
   再估计发生率和分布，否则只做声明清楚的压力情景与敏感性分析。
5. **决策流程。** 核心验证后再将可审计快照、假设编辑、响应轨迹和风险偏好接入终端/UI。
   当前不包含实况部署或实时比赛建议。
