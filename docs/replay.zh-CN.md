# 带时间边界的下一圈回放

[English](replay.md) · [缓存/CSV 交接](real-data-import.zh-CN.md)

`f1-replay` 导入规范化缓存导出，先冻结决策数据，再读取独立后续观测，只检查已有模型的
下一圈预测。当前限个人目标快照与完整同圈车阵，不代表整场策略验证、概率校准或因果收益。

```sh
python -m f1_strategy_optimizer.replay --input examples/replay-synthetic.json \
  --output-dir output/replay-demo
# 安装后：f1-replay --input /path/to/trusted-export.json --output-dir output/replay-real
```

两个示例案例**完全合成**，后续结果手工构造；development/holdout 日期仅验证分区逻辑，
并未用这些日期对应的真实比赛训练模型。

## 输入契约

完整 JSON 形状见示例，不能把合成记录改名成真实观测。

| 对象 | 最小要求 |
|---|---|
| `provenance` | synthetic/observed、来源、URI、获取时间、处理说明 |
| `splits` | 带时区的训练截止与更晚的留出开始时间 |
| case | 唯一标识、development/holdout 分区、decision 与独立 outcome |
| `decision` | 决策/观测/可用/假设可用时间，完整车阵声明，每车已完成圈数，模型类型/训练截止，planning |
| `planning` | 既有规划器输入；明确赛季/赛事、可见条件、全场间距/轮胎/胎龄/车队，以及独立标注的速度、模型、对手和情景假设 |
| `outcome` | 更晚的观测/可用时间、紧接下一圈、全场位置/间距/配方/胎龄、赛道/天气、完整已知进站行动及其边界 |

时间戳必须带时区。观测须在决策前获得；获取文件的时间不等于当时可用时间。快照必须
对齐同一决策边界，不能把每车各自完成圈的记录拼成同时可见状态。来源导出器须证明
对齐/可用性；适配器检查声明一致性，不能独立证明用户来源真实。

所有初始车辆必须同圈，下一圈结果必须包含同样的全部车手。缺车、退赛、套圈、未知
进站、缺失条件会明确拒绝评分，不插值或默认补天气。未知库存保留为模型中的不限量，
不声称库存可行；启用最低进站/已用配方规则时需提供历史次数/配方。真实车辆基准速度
仍是需审计的估计，不能直接把公开圈速当作已识别的车辆性能。

`model_kind=assumed` 的训练截止必须为 null；`fitted` 必须有不晚于决策的截止时间，
留出案例还不能超过全局训练截止。留出决策需处于声明的留出时段。拟合来源、清洗过程
记入 provenance；提供系数并不等于已验证模型。后续轮胎配方须与记录的进站一致。

## 决策隔离与基线

适配器复制并验证 decision，**先完成规划并记录决策输入哈希，再读取 outcome**。
不使用未来结果补齐状态、更新权重、选择对手或计划；情景仍须为决策时已声明的假设。
不能把已知后来发生的 SC/天气改标为早先假设。改写或删除后续结果不改变推荐。

在同一状态、候选、对手、情景与约束下比较：名次优先、同候选最短模拟用时、继续跑。
时间基线复用已有候选用时指标，**不冒充单车 DP 精确最优解**，也不把起始旧胎重置为新胎。
整场预期名次/用时仍是模拟；只将第一圈预测与独立下一圈结果比较。

每种方法在全部情景中的**全场当前进站行动**必须与观测相同，否则记 `action_mismatch`，
误差为空。不丢弃不匹配情景后重新加权。行动匹配时计算加权预测名次/间距对实际值的
绝对误差；突发天气或 SC 留作预测误差，不回填进决策。该条件样本可能有选择偏差，
不能估计未发生策略的因果收益，也不评价以后尚未执行的计划。

development/holdout 分开报告案例数、车手观测数、错误与未匹配数量。只有两种方法共同
可评分的案例才计算配对误差差值；不能直接比较覆盖率不同的均值。零覆盖输出 null，
不输出伪造的零误差。同场观测相关，本轮不提供置信区间。

## 预算与输出

每批最多 100 个案例，保留单次搜索上限，并有总仿真预算 `max_total_rollouts`（默认
10000）。预算不足的案例明确不评分，顺序由输入决定，不自动重试或放宽规则。
输出 `replay.json`、可读 `replay.md` 和含原始输入/哈希/版本的清单，拒绝覆盖。
存在拒绝、预算耗尽、无可行候选，或无名次方法可评分时，CLI 返回 2 并保留部分证据。
有效输入中基线行动不匹配属于覆盖限制，不当成解析错误。

## 当前缺口与下一步

这是**规范化导出适配器，不是原始 FastF1 缓存的自动解码/对齐器**。可信规范化导出可
直接运行；只有原始缓存时，需先检查真实字段并写窄范围来源导出器，审计共同时间边界，
不能猜造间距、进站或可用时点。仅有清洗圈速 CSV 不足以还原已排除的进站/非绿旗信息。

以下为早先实例的历史状态：当时未获得可信真实数据。2026-10-17 对三个原配置来源各做一次正常请求，仍在代理
HTTPS CONNECT 阶段被 403 拒绝，未收到来源服务器响应。详见[本轮验证记录](replay-validation-2026-10-17.md)。
下一步是取得一段完整同圈真实状态及独立后续观测，再扩展留出比赛覆盖和失败分析；
先验证已有机制，不继续增加赛事机制。

新实例随后已取得 OpenF1/Jolpica 巴林归档，见[事件时间观测基准](event-replay.zh-CN.md)。
该入口报告真实开发预测误差；行动和完整状态证据不足时，严格策略评分仍保持为空。
