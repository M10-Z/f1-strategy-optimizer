# 名次导向多车策略规划

[English](competition.md)

核心目标是面对不同车辆性能及会响应的对手争取更好的完赛名次。当前实现比较有限候选
在明确假设下的结果，不是博弈论最优解、真实校准预测或可直接用于比赛的控制系统。

## 架构与复用

| 层 | 实现 | 职责 |
|---|---|---|
| 已有轮胎接口 | `solver.LapTimeModel` | 配方/胎龄/温度圈速；Python API 可直接传入已有拟合 `TyreModel` |
| 可见状态 | `RaceState`、`CarState`、`Observation` | 已完成/总圈数、全场顺序和间距、车辆基准速度、轮胎及可见赛道状态、已发生进站 |
| 对手决策 | `OpponentPolicy.choose` | 固定计划或 undercut/overcut 响应，不接收未来事件对象 |
| 事件假设 | `Scenario`、`RaceEvent` | 显式加权的假设 SC/VSC、天气和温度路径 |
| 竞争仿真 | `Physics`、`simulate` | 同时进站决策、时间损失、胎龄、受限超车、中立化 |
| 名次目标 | `candidate_actions`、`candidate_plans`、`plan_positions` | 兼容首版，支持有界二停及车队名次和目标 |
| 资源与控制 | `CompetitionRules`、`rolling_plan` | 显式库存/规则约束、同队排队、按可见状态逐圈重新规划 |
| 联合控制 | `joint_planner.plan_joint_positions` | 双车有限快照搜索，每车代价与未搜索范围明确输出 |
| 离线入口 | `race_planner`、`f1-race-plan` | JSON 输入、来源/哈希/版本记录、JSON 与 Markdown 排名 |

单车动态规划继续用于孤立环境的最短模型时间基线，不负责求解交互竞争。
复用已有轮胎接口、拟合、验证和来源记录，不改变其含义。CLI 使用用户提供的线性轮胎
曲线，可包含半雨/雨胎名称，但不是拟合过的真实湿地模型。
车辆圈速为 `base_lap_time + tyre_prediction - reference_lap_time`。
CLI 线性曲线不建模温度响应；Python 模型接口允许其他模型提供该响应。

## 时间与信息边界

在完成第 L 圈的决策点：

1. 所有车手读取同一不可变状态，以及严格早于 L 的已完成进站记录。
2. 先收集所有行动，再暴露任何行动；不能窥见其他车手同时做出的决定。
3. 按当前可见赛道状态收取进站损失，换胎后胎龄归零。
4. 揭示假设的第 L+1 圈事件，按胎龄加一计算该圈。
5. 更新名次与间距，本次进站在下个决策点才对其他车手可见。

`cover_undercut` 可在可见间距/窗口内观察到对手进站后提前防守；`overcut` 可延长
计划赛段。两者持续检查当前间距，不能同一时刻响应尚未观察的进站。
`observed_pits` 支持从已知历史重新规划，拒绝决策当圈及未来的进站记录。

事件是整圈近似，不是圈内精准部署。未来列表仅由仿真器持有，对手策略没有该引用。
情景必须标为 `hypothetical`，且 `available_at_lap` 不晚于决策点；拒绝历史未来类型。
这些检查保证接口的信息边界，无法证明用户填报来源为真。把真实未来事件改标为假设
仍属于后见泄漏；真实回放适配器必须只用此前信息生成信念，目前该适配器尚未实现。

## 交通、事件和不确定性

- 全部车辆均在赛中且处于同一圈。初始间距决定位置，相同间距按输入顺序。
  进站支付时间损失后可改变重返赛道顺序。
- 超车需满足模型速度优势与超车成本后的空间条件，每车每圈最多超越一车；
  否则受前车阻挡。它是显式近似，不是 DRS、空气动力学或连续距离模型。
- SC/VSC 禁止赛道超车，但允许进站带来的位置变化。SC 每圈有限收拢间距，
  不快于对应绿旗行驶；VSC 不主动压缩队列。减速与进站损失缩放由用户提供，
  同一决策点的同队排队按到达间距近似，尚无具体维修区几何及 SC 部署阶段。
- 雨天改变显式的分配方损失，允许换胎权衡；湿地情景必须提供每种配方的损失，
  不猜测未知配方响应。
- 权重只表示用户假设，不是测得的发生频率。报告加权平均名次、完整名次分布、
  最差名次、标准差及跌出前 k 的加权份额。先按平均名次、再按最差名次排序；
  完全相同优先不进站，再按稳定标签排序，不以总时间最小为最终目标。
- 每轮搜索比较零/一/二停方案；滚动控制器只执行当前行动，再按下一圈观测重新规划，
  持续保留库存与历史。这是有界滚动搜索，不是全局最优自适应策略树。
- 可选车队名次和目标会改变自车计划，队友仍按提供的策略行动。库存、规则子集、预算、
  排队及其限制详见[资源约束与滚动规划](resources-and-replanning.zh-CN.md)。

## 可复现合成示例

```sh
python -m f1_strategy_optimizer.race_planner \
  --scenario examples/competition.json --output-dir output/position-plan
```

示例为原创四车、剩余 8 圈、13 个候选和 4 个等权压力情景（绿旗干地、SC、VSC、雨）。
输出 `race-plan.json`、`race-plan.md`、`manifest.json`，包含原始输入及 SHA-256，
拒绝覆盖已有输出。不请求网络，也不把任意随机概率冒充真实校准。

本例实测的软件行为，**并非真实比赛效果**：

| 对手假设 | 排名最高的行动 | 情景加权完赛名次 |
|---|---|---:|
| LEADER/FAST 响应式，TRAFFIC 固定 | 继续跑 | 2.25 |
| 全部对手按原定圈数固定进站 | 第 45 圈后换 HARD | 1.00 |

同一个“第 45 圈后换 MEDIUM”方案，对手固定时所有情景均为 P1；对手响应时
P2 权重为 0.25、P3 为 0.75。干地情景中 LEADER 在第 46 圈后响应，而不是等到 49。
这说明“对手不动”的假设会显著改变模拟推荐，不证明哪种对手模型真实，也不证明
示例等权参数合理。

## 真实可行性与后续证据

尚无真实名次预测精度或策略收益验证；计时来源被环境代理拒绝，详见
[获取尝试记录](real-validation-2026-10-17.zh-CN.md)。公开圈速混合车辆性能、交通、
燃油、轮胎、赛道演化和车手行为，不能视为已识别的因果车辆性能。

下一优先级是取得可信数据，验证决策快照/回放、真实间距与超车、进站损失及对手响应。
有限新胎库存、显式规则子集、二停滚动规划和同队排队已实现；[双车联合快照搜索](joint-planning.zh-CN.md)
也已实现。旧胎重用、双车自适应控制、
故障、处罚、套圈、红旗仍待实现。事件分布需要真实数据证据后才能校准。
不声称穷尽所有影响结果的因素；详见[路线图](roadmap.zh-CN.md)。
