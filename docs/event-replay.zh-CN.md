# 真实事件时间回放与事实预测基准

[English](event-replay.md) · [本轮真实开发结果](event-replay-validation-2026-10-17.zh-CN.md)

本入口把已归档的 2023 巴林站数据转为统一 UTC 截止的可见状态、冻结预测和独立结果。
它提供可复现的历史研究内核。巴林已参与开发，所有结果标为 development，不能称独立留出。
现有 `f1-replay` 继续处理具备完整行动及状态证据的规范化策略回放，两者语义不混用。

## 本地运行

```sh
python -m f1_strategy_optimizer.event_replay \
  --openf1-dir /workspace/real-data/openf1-2023-bahrain \
  --jolpica-dir /workspace/real-data/jolpica-2023-bahrain \
  --cutoffs examples/bahrain-event-cutoffs.json \
  --output-dir output/bahrain-event-development
# 安装后同样可以使用 f1-event-replay
```

入口离线读取已验证响应，拒绝覆盖输出目录。原始数据及输出不提交 Git。
数据目录包含 OpenF1 `sessions/drivers/laps/stints/weather/race_control/position/intervals.body`
及对应 `.meta.json`，同场 `jolpica-results.body` 及凭据；Jolpica 目录含
`raw/laps-NNNN.json`、`raw/pitstops-NNNN.json` 和对应 `.meta.json`。
文件大小、SHA-256、成功 HTTP、URL 过滤条件、赛事身份和唯一键都会校验。
Jolpica 分页按实际车手计时数累计 offset，检查 total 一致、无缺页/重叠/重复。
此适配器目前有意限定这场比赛，不能把其他场次改名后导入。

身份使用同场 `Results.number` 加姓名核验，仅导出车手 ID、当场用号、姓名和车队。
当前 `permanentNumber` 可能与历史用号不同。最终名次、耗时和退赛信息不进入决策。
两来源首圈的 20 条差异单列审计；预测只用 OpenF1，训练排除首圈，不混合定义。
3 条无圈时记录只保留为开始事件，不视为完成圈或退赛证据。

## 时间与字段契约

默认假设发布延迟 2 秒，加近似圈起始时间安全余量 1 秒；均为研究假设。
可用 `--policy policy.json` 覆盖 `EventTimePolicy` 字段。每个字段保留来源、事件时间、
假设可用时间、观测年龄和 observed/inferred/unknown 状态。没有历史 publication time，
所以不能声称重现了当时在线系统真正可见的信息。

- 所有车使用同一 UTC cutoff；完成圈数允许不同。间距和位置是截至 cutoff 的最后已知
  异步报文，不重新按间距排序、不伪造完整同时刻顺序、不用未来更新回填。
- 完成圈要求相邻下一圈开始事件已可见，且
  `max(start + duration, next_start) + delay + margin <= cutoff`。
  缺少下一圈开始的终场记录会损失训练覆盖，这是明确的保守限制。
- 当前开始圈仅暴露圈号/开始时间。其未来圈时、后续配方、进站、赛会消息及天气不进入前缀。
- 当前 stint 通过可见 `lap_start` 对应开始事件判断，永不读取 `lap_end` 选择或预测。
  配方和胎龄的可用性是假设附着于该开始事件，胎龄按已证实完成圈推算；不是已验证发布记录。
- 赛会消息保留原文。`GREEN LIGHT - PIT EXIT OPEN` 不视为全赛道绿旗，
  `VIRTUAL SAFETY CAR ENDING` 不视为已结束。rainfall=0 也不直接推出 DRY。
  当前全场状态、路面条件、活动/退赛车阵和轮胎库存保留 unknown。

## 预测、行动和评分

全部时间点在读结果前固定，所有预测写入 `decisions.json` 后才开始评分。
冻结记录包括代码文件哈希、配置、种子、可见前缀哈希、拟合截止、模型参数、目标、
候选预测/拒绝原因及推荐。种子为可复现接口预留，本轮算法无随机采样。
完整归档哈希另存运行清单，未来文件追加不会改变既有可见前缀哈希。
此不变性针对通过来源校验的有效归档；删除必需字段或破坏来源哈希会先被导入器拒绝。

逐车完整圈时目标为 cutoff 前最新可见开始圈的下一圈。若揭示后目标已在 cutoff 前开始、
缺失或无时长则明确排除，不自动换到另一圈。模型用最近最多 8 个已完成且非首圈、非已知
出站圈的样本，至少 3 条，拟合有斜率上限的逐车线性外推；比较相同前缀的中位数和
最后一条合格完成圈基线（`last_eligible_completed`）。
车辆各用自己的前缀，但这不等于独立识别车辆性能或轮胎退化。
未来进站、SC/VSC 和天气导致的误差保留，不用未来条件筛掉困难样本。

间距目标是 cutoff 后 90 秒时最后已假定可用的**新报文**，不是物理位置同步真值。
输入/结果报文默认最多老 12 秒；只接收有限数字，null 或 `+1 LAP` 不转成 0。
前缀 60 秒趋势与原值保持基线在相同可评分样本上比较。
报告圈时和间距的尝试数、评分数、排除原因、MAE 及配对 MAE 差，零覆盖为 null。

这两项均是无条件事实观测预测，**不是 stay-out 行动策略评分**。
留场和三种干胎进站候选均记录 requested_at；由于缺少已验证行动生效时点、精确进站边界、
同步车阵和因果速度模型，effective_at、预测和推荐保持 null，状态 blocked。
本场 OpenF1 pit 接口 404，Jolpica 只有圈号级记录，不能据此凑全场行动匹配。
严格策略指标保持 null。以后具备完整证据的候选也必须先冻结预测，再按全场实际执行动作
匹配评分；未执行候选只能称模型反事实，不能解释为实际策略收益。

## 输出与下一轮验收

`decisions.json` 可独立保存/审查；`evaluation.json` 包含隔离结果、覆盖、来源凭据、版本和耗时；
`evaluation.md` 提供简短摘要。修改冻结记录后哈希校验失败。
首次运行固定十个时点，覆盖赛前、早段、进站窗口、中段、VSC 附近、末段和赛后，
所有 20 名注册车手保持在分母中，不依未来退赛信息选车或缩分母。

产品路线：先把这条离线流程做成可操作的历史回放/策略比较界面，再扩展策略机制。
界面需选车/UTC 时点、前三个**可行**方案（含留场）、前后车威胁、出站交通、队友代价、
假设敏感性、点击揭示实际结果和导出冻结记录。缺证据时显示不可推荐原因，不能填充假方案。

下一轮验收：补齐一段经审计的共同时间边界和行动证据，验证当前事件重建、字段时效和
动作生效顺序；新增不同延迟下的覆盖敏感性；先冻结一整场未参与调参的留出赛事及评分规则，
再开展车辆性能/对手策略建模。相邻圈不随机打散。只报告事实匹配预测误差及共同覆盖，
不把模拟名次收益或一场开发数据称为实战效果。商业部署前另行核验来源使用权益。

## 保守默认值与假设探索

现默认采用此前巴林开发支持的圈时前缀中位数和间距保持值，当前赛段中位数作为实验对照。严格事实策略评分仍为空；独立的显式假设探索器可输出模拟选项。见[UI/API 接口](exploration-ui-contract.zh-CN.md)与[整场预注册](../examples/whole-race-holdout-lock.json)。
