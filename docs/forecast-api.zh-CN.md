# 可审计的圈时预测接口

本接口把既有 v1 条件圈时预测、逐车弃权原因及证据时效统一提供给前端。它没有训练新模型，也没有证明预测精度提高。v1 的独立验证改善 3.75%，未达到预注册的 10% 门槛；v2 仍为未通过验收的实验，不是默认模型。完整结果见 [新鲜度验证](freshness-validation.zh-CN.md)。

## 本地运行

```sh
python -m f1_strategy_optimizer.workbench
```

访问 `http://127.0.0.1:8765`。先从 `/api/catalog` 取得 case ID，再请求：

```text
GET /api/forecast?case=<URL编码的case ID>
GET /api/forecast?case=<URL编码的case ID>&driver=leclerc
```

不指定 driver 时返回快照内所有车手；不存在的 case/driver 返回 HTTP 400，不默默选择替代项。响应禁止缓存。接口只读冻结决策与前缀上下文，绝不读取揭晓文件。实际结果仍需要单独点击揭晓，并由原有接口处理。

## 字段与含义

- `mode=historical_replay`、`live_ready=false`：历史复盘，不能作为实时比赛指令。
- `model`：默认 v1 及其未通过验收状态。
- `summary`：所选范围内车手数、产生条件预测数、弃权数与原因计数。不是准确率。
- `drivers`：车手身份、固定目标圈、预测秒数、样本圈号/完成时间、完成圈时效、间距质量、未知活动状态及阻止实时使用的原因。
- `predicted_lap_seconds=null`：当前不能提供条件参考。前端应显示 `reason_zh`，不可显示 0 或回填旧预测。
- `gap.value_seconds=null`：间距不可用或过期；原始非数字、套圈等报告保留在 `raw_reported_value`，不可补零。
- `target_start_verified=false`：目标开始时刻没有核验，不能偷换目标圈来制造可用预测。
- `observed_range_seconds`：输入样本极差，不是置信区间。`prediction_interval=null`，不提供未经校准的概率。
- `source_sha256`、`context_sha256`、`decision_sha256`：可审计来源。
- `report_sha256`：响应去除 `case` 和 `report_sha256` 后的规范 JSON 摘要，与项目 `event_replay.digest` 一致。它检查记录一致性，不认证来源，也不是电子签名。

## 距离真实可用仍缺什么

1. 获授权且完整的真实输入，保存原始消息、可靠接收时间及源发布时间证据。目前打包样例只有巴林三个历史时点。
2. 可信圈边界、进站出口、活动/退赛状态，以及同步车阵、轮胎库存等决策所需信息。
3. 在开发数据上分析误差，提前登记新的候选、完整赛事留出和 MAE/P95/覆盖门槛，再进行独立评估。已经看过的赛事不能重新宣称未触碰测试。
4. 独立评估通过后才考虑替换默认模型；仍需校准预测区间及实际部署的延迟/失效模式。观测圈时误差不是策略因果收益。

接口提供的是有边界、可检查的预测服务，而不是把缺失证据包装成可用性。本次无需新增账号、凭据或订阅。

## 最小真实开发审计（2026-11-04）

```sh
python -m f1_strategy_optimizer.development_audit --output-dir output/my-new-development-audit
```

输出目录必须是新路径。工具只允许内置巴林开发样例：先保存当前模型的预测与 SHA256 收据，才读取已有揭晓，核对预测/固定目标一致、目标在截止点后开始，并独立重算候选和旧中位数的配对误差。若预测与原档案不一致则失败，不把旧分数冒充新模型成绩。不开放自定义赛事入口，防止意外重跑封存测试。

本次结果：3 个既有开发时点、60 个车手时点；37 个评分、19 个主动弃权、4 个目标缺失，覆盖 61.67%。v1 配对 MAE 1.033676 秒，旧中位数同目标 MAE 1.148797 秒；v1 P95 为 2.863 秒（nearest-rank 定义），最大误差 20.128 秒。该最大误差来自 Gasly 第 10 圈，预测 101.134 秒、实际 121.262 秒。这些是既有模型在已观察小样本上的复现，**不是本次精度提升，也不是新的独立验证**。

同时对已观察的巴林开发场执行两个普通、有界公共 GET：会话发现及 `https://api.openf1.org/v1/laps?session_key=7953`。两次均 HTTP 200，无凭据；圈数据 526,418 字节、1,058 条，37 个评分目标的实际圈时全部与打包数据一致。公开源将 Gasly 第 10 圈标记为出站圈，暴露未来动作变化造成的大误差风险；这个事后标签没有进入预测，也没有用于删去难例。该复核来自同一提供方，不是独立供应商交叉验证，不证明消息实时发布时间。

下一步应先在已观察开发数据上建立未来动作/状态变化造成的失效诊断，获取可验证的动作生效/圈边界证据，再冻结一个新候选及独立验证方案。不能因这一小样本的较低 MAE 就绕过旧独立测试失败结论。

### 动作转换的事后诊断

```sh
PYTHONPATH=src python scripts/diagnose_bahrain_transitions.py \
  --laps <本地巴林2023 OpenF1圈数据JSON> \
  --output-dir output/my-new-transition-diagnostics
```

诊断先重现并保存既有预测，再读入事后动作标签。输入限定 session 7953 / meeting 1141，并要求所评分目标圈时与已审计观测一致。它不会修改模型或原始数据。

2026-11-04 结果：37 个评分目标里，1 个目标出站圈占总绝对误差的 52.63%，2 个“下一圈是出站圈”的目标占 14.56%；合计 3 个样本占 67.19%。其余 34 个目标的 MAE 为 0.369 秒，但它只是事后分组的描述，不能删去动作相关样本后当作实际预测精度。所有分组仍保留总体 60 个槽位、37 个评分与 1.033676 秒 MAE。

15:18 截止时，Gasly、Tsunoda、Norris 最近三个完成圈均稳定，前缀仍显示软胎、完成胎龄8圈；目标第10圈尚未开始。事后出站标记没有当时可见的源发布时间或车队行动意图，不能回填成模型输入。下一圈为出站圈只是一种关联代理，不是经核验的进站入口时刻；圈时也混合交通、轮胎及其他效应，不能将分组误差解释为因果净进站损失。

这三时点的数据不足以支持一个可靠的新前缀预测器，本次没有调参数或更改默认模型。最有价值的下一份证据是预测截止前已知的行动计划、可信进出站/圈边界及其发布时间；随后在更完整的已观察开发数据上检验是否有可重复的提前信号，再预先冻结独立验证方案。诊断测试确保改变事后动作标签不会改变预测、分母或总体误差。

诊断标签的优先级为：目标本身明确为出站圈；否则下一圈明确为出站圈；只有目标和下一圈两个标记均明确为 false，才归为“未观察到进站关联”；缺失下一圈或非布尔/缺失标记则单列 `transition_label_unavailable`。报告同时给出完整评分分类、60槽位覆盖、已知/未知标签数及全部分组，不能把无法判断当作正常圈。新增定向回归覆盖下一圈代理、双true优先级和缺失/非布尔标签。

诊断工具对调用方传入的圈数据仅检查结构、赛事标识及已评分圈时一致性；没有验证独立来源收据。输出明确 `source_receipt_verified=false`、来源未核验。它不能仅靠内容匹配认证文件来自OpenF1；本轮公共请求的响应头与原文由人工审计另存，工具不会自动假定这些证据存在。
